### layoutViewport

```ts
function layoutViewport(design: ViewportDesign, screen: {
    readonly width: number;
    readonly height: number;
}, insets: ViewportInsets, resolution: number): Viewport;
```

Lays the design frame out on a screen. The design width fills the safe area's width, and the
logical height grows to fill its height; a safe area too short for `minHeight` scales the
frame down further, keeps the height at `minHeight` and centres the frame horizontally.
`pixi2d({ design })` uses it to set the `Viewport` resource. It is pure, so browser tests can
turn design units into click positions with the same rule: `logicalToScreen(layout, point)`.

```ts
const layout = layoutViewport({ width: 390, minHeight: 520 }, { width: 390, height: 844 }, { top: 47, right: 0, bottom: 34, left: 0 }, 3);
logicalToScreen(layout, { x: 195, y: 100 }); // CSS pixels from the canvas corner
```

### pixi2d

```ts
function pixi2d(options?: Pixi2DOptions): Pixi2DPlugin;
```

The PixiJS 2D renderer as a game plugin. Registers `fenrir.pixi.init` (Init),
`fenrir.viewport.init` (Init, after it), `fenrir.viewport.preUpdate` (PreUpdate, applies resizes),
`fenrir.pixi.postUpdate` (PostUpdate: writes `Transform2D` and `Display2D` to `PixiNode` and
`Renderable2D` entities, then renders; `renderer.render()` does the same sync) and `fenrir.pixi.exit` (Exit, unmounts and destroys nodes). Keeps the `Viewport` resource and sends `ViewportResized`.

```ts
const pixi = pixi2d({ design: { width: 390, minHeight: 520 }, background: 0x101820 });
const game = await createGame({ canvas, plugins: [pixi] });
pixi.renderer.root; // draw here in design units, once the game runs
```

### screenToLogical

```ts
function screenToLogical(viewport: Viewport, point: ViewportPoint): ViewportPoint | null;
```

Converts a point on the screen (CSS pixels from the canvas's top-left corner) into logical
units. Returns null while the viewport has no area (scale 0).

## Classes

### PixiRenderer

```ts
class PixiRenderer {
    readonly root: PIXI.Container<PIXI.ContainerChild>;
    readonly backdrop: PIXI.Container<PIXI.ContainerChild>;
    constructor(options: PixiRendererOptions);
    layer(name: string): PIXI.Container;
    attachNode(entities: EntityList, entity: Entity, value: PixiNode): void;
    detachNode(entity: Entity, value: PixiNode): void;
    releaseNodes(entities: EntityList | undefined): void;
    unmountNodes(): void;
    get app(): PIXI.Application;
    init(): Promise<void>;
    get initialized(): boolean;
    resize(width: number, height: number, resolution?: number): void;
    applyViewport(viewport: Viewport): void;
    clientToLogical(clientX: number, clientY: number): ViewportPoint | null;
    logicalToClient(x: number, y: number): ViewportPoint | null;
    upsertRenderable(entities: EntityList, entity: Entity, renderable: Renderable2D): Promise<void>;
    removeRenderable(entity: Entity, renderId: number): void;
    syncTransforms(entities: EntityList): void;
    bindScene(entities: EntityList | undefined): void;
    render(): void;
    clearRenderables(): void;
    dispose(): void;
    getRenderedObject(entity: Entity, renderableId: number): PIXI.Container | undefined;
}
```

The 2D renderer behind `pixi2d()`, as `plugin.renderer`. Game code adds Pixi content to `root` (logical units) or `backdrop` (full-bleed CSS pixels), or reads a named layer with `layer(name)`.

Members:

- `root`: Game content, drawn in logical units. `pixi2d` scales and positions it to the design frame; without `design` it is unscaled at the top-left. Entities with `Renderable2D` mount here.
- `backdrop`: Full-bleed content behind `root`, in CSS pixels from the screen's top-left corner, unscaled. Cover `Viewport.screen` to fill the whole screen, outside the frame and the safe area too.
- `layer`: The container of a layer from `pixi2d({ layers })`: a child of `root`, in logical units, its children sorted by `zIndex`. `"fenrir.backdrop"` returns `backdrop`. Throws for an unknown name, listing the declared ones.
- `attachNode`: Mounts an entity's `PixiNode`, replacing the node it had. Internal: the renderer system calls it.
- `detachNode`: Unmounts `value.node` after an entity's `PixiNode` was removed. Internal.
- `releaseNodes`: Unmounts every node at stop. Destroys the ones not kept and removes their `PixiNode` components, so a later run never mounts a destroyed node. Internal.
- `unmountNodes`: Unmounts every node without destroying any, when the active scene changes. Internal.
- `applyViewport`: Places `root` for `viewport`: at its offset, at its scale. Called by `pixi2d` when the layout changes. Internal.
- `clientToLogical`: Converts CSS client coordinates (a DOM event's `clientX`, `clientY`) into logical units: design units with `pixi2d({ design })`. Returns null while the canvas or frame has no area.
- `logicalToClient`: Converts logical units into CSS client coordinates. The inverse of `clientToLogical`.
- `syncTransforms`: Writes transforms to every node and renderable view and mounts each under its parent. Runs once a frame, before rendering. Internal.
- `bindScene`: Sets the entities `render()` syncs. Internal: the renderer system binds the active scene.
- `render`: Syncs every node and view with its entity's `Transform2D` and `Display2D`, then renders. `fenrir.pixi.postUpdate` calls it each frame; game code may call it to draw outside a frame, for example from a startup system, and sees the same synced scene.

## Constants

### PixiNode

```ts
type PixiNode = {
    readonly node: Container;
    readonly layer?: string;
    readonly keep?: boolean;
};
const PixiNode: ComponentType<PixiNode>;
```

A Pixi display object the app built, owned by an entity. The 2D renderer mounts `node` in
`layer` (a name from `pixi2d({ layers })`), or under the node of the entity's parent when the
parent has one, or in `renderer.root`. `layer: "fenrir.backdrop"` mounts it in
`renderer.backdrop` instead, where `Transform2D` is in CSS pixels from the screen's corner.
Every render writes the entity's `Transform2D` and `Display2D` to it first; without them the
app positions and shows the node itself. A child entity's node sorts by `zIndex` under its
parent's node: Pixi turns `sortableChildren` on when a child has a non-zero `zIndex`.

When the component or the entity is removed, or the run stops, the renderer removes `node`
from its parent and destroys it with its children (not their textures). With `keep: true` it
only removes it from its parent, and at stop the component stays so the next run mounts it
again. A destroyed node's component is removed at stop.

### Viewport

```ts
interface Viewport {
    readonly width: number;
    readonly height: number;
    readonly scale: number;
    readonly offset: ViewportPoint;
    readonly insets: ViewportInsets;
    readonly screen: {
        readonly width: number;
        readonly height: number;
    };
    readonly resolution: number;
}
const Viewport: ResourceType<Viewport>;
```

Where the game's logical frame sits on the screen. Plain data: a new object each time the
layout changes, so a held reference is a snapshot.

"Screen" is the canvas, in CSS pixels from its top-left corner.

Members:

- `width`: Logical width: the design width, or the screen width without `design`.
- `height`: Logical height: at least the design's `minHeight`, or the screen height without `design`.
- `scale`: CSS pixels per logical unit. 0 while the safe area is empty.
- `offset`: Top-left corner of the logical frame on the screen, in CSS pixels.
- `insets`: Safe-area insets in use, in CSS pixels. All 0 with `safeArea: false` or without `design`.
- `screen`: The whole screen (the canvas), in CSS pixels. Full-bleed content covers this.
- `resolution`: Backing-store pixels per CSS pixel: `devicePixelRatio`, capped by `maxResolution`.

### Pixi2DOptions

```ts
interface Pixi2DOptions {
    readonly design?: ViewportDesign;
    readonly safeArea?: boolean;
    readonly maxResolution?: number;
    readonly background?: number;
    readonly application?: PIXI.Application;
    readonly width?: number;
    readonly height?: number;
    readonly layers?: readonly string[];
    readonly applicationOptions?: PixiRendererOptions["applicationOptions"];
}
```

What `pixi2d()` takes: the design frame, layers, background and Pixi application options. Every field is optional.

Members:

- `design`: The size the game is designed for, in logical units. With it the plugin owns the canvas size: the canvas fills the window, the design width fills the safe area's width, and the logical height grows from `minHeight` to fill its height. A safe area too short for `minHeight` scales the frame down and centres it horizontally. Game content in `renderer.root` is drawn in these units. Without it, logical units are CSS pixels and the canvas keeps the size it was created with.
- `safeArea`: With `design`, lay the frame out inside `env(safe-area-inset-*)`. Defaults to true.
- `maxResolution`: Caps backing-store pixels per CSS pixel: `min(devicePixelRatio, maxResolution)`. Defaults to 2.
- `background`: Clear colour, as 0xRRGGBB. A Pixi application the plugin creates defaults to 0x101010. An adopted `application` keeps its own unless this is given, which sets it when Init runs.
- `application`: A Pixi application the app already owns, initialized on the game's canvas with its ticker stopped. The game renders it but does not destroy it at exit.
- `width`: Size of a Pixi application the plugin creates, without `design`. Defaults to the window size.
- `layers`: Named layers under `renderer.root`, back to front. An entity's `PixiNode` picks one by name; `renderer.layer(name)` returns its container. Content added straight to `root` draws above every layer, and `renderer.backdrop` stays behind them all; a `PixiNode` mounts there with the layer name `"fenrir.backdrop"`. Names starting with `fenrir.` are reserved and throw.
- `applicationOptions`: Other initialization options for a Pixi application the plugin creates.

### Pixi2DPlugin

```ts
interface Pixi2DPlugin extends Plugin {
    readonly renderer: PixiRenderer;
}
```

What `pixi2d()` returns: a plugin for `createGame`, with the renderer it installs.

Members:

- `renderer`: The renderer, for game code that draws with Pixi directly: add content to `renderer.root` (logical units, scaled to the design frame) or `renderer.backdrop` (full-bleed, CSS pixels). Available once `createGame` has installed the plugin; its Pixi application is initialized when the game's Init stage runs.
