## Functions

### bootstrapEngine

```ts
function bootstrapEngine(engine: Engine, logger: ILogger, config: BootstrapConfig): BootstrapResult;
```

Bootstrap the 3D engine systems with sensible defaults

This creates and configures the systems a 3D game needs:
- Input handling
- Rendering (WebGL/WebGPU through Three.js)
- Camera management
- Skybox rendering
- Optional: Physics, Animations, Performance stats

A 2D game does not use this: it registers the systems from `fenrir-ts/2d` itself.

### ThreeRenderer

```ts
class ThreeRenderer {
    readonly scene: THREE.Scene<THREE.Object3DEventMap>;
    readonly camera: THREE.PerspectiveCamera;
    readonly requestedRendererType: RendererType;
    constructor(opts: ThreeRendererOptions);
    get renderer(): AnyRenderer;
    get rendererType(): RendererType;
    init(): Promise<void>;
    get initialized(): boolean;
    resize(width: number, height: number);
    upsertRenderable(entities: EntityList, e: Entity, r: Renderable);
    removeRenderable(e: Entity, renderId: number);
    syncTransforms(entities: EntityList);
    renderWithCameras(cameras: Array<[
        Entity,
        CameraInstance
    ]>, _ecsScene?: Scene, skyboxInstance?: SkyboxInstance | null);
    render(skyboxInstance: SkyboxInstance | null);
    renderWithCamera(camera: THREE.PerspectiveCamera | THREE.OrthographicCamera);
    getRenderedObject(entity: Entity, renderableId: number): THREE.Object3D | undefined;
    dispose();
    getCurrentSkybox(): SkyboxInstance | null;
    removeSkybox();
}
```

Members:

- `requestedRendererType`: Requested renderer type. See `rendererType` for the one in use.
- `renderer`: The underlying three.js renderer. For `"webgpu"` it exists only after `init()` resolves.
- `rendererType`: Renderer type in use. Starts as the requested type and becomes `"webgl"` after init() if WebGPU was requested but is unavailable.
- `init`: Initialize the renderer. For `"webgpu"` this loads `three/webgpu` and creates the renderer; without WebGPU it logs a warning and uses WebGL instead.
- `initialized`: Check if renderer is initialized
- `upsertRenderable`: Call when Renderable is added or replaced (if geometry/material can change).
- `removeRenderable`: Call when Renderable is removed or entity destroyed.
- `syncTransforms`: Sync transforms for all renderables each frame.
- `renderWithCameras`: Render with cameras
- `render`: Legacy render method (kept for backward compatibility)
- `renderWithCamera`: Render with a specific camera
- `getRenderedObject`: Get the rendered Three.js object for an entity/renderable ID
- `getCurrentSkybox`: Get the current skybox instance
- `removeSkybox`: Force remove skybox from scene

### Transform

```ts
type Transform = {
    position: Vector3;
    rotation: Quaternion;
    scale: Vector3;
};
const Transform: ComponentType<Transform>;
```

The engine's `fenrir.Transform` component, typed with Three's classes.

It is the same component as `Transform` from `fenrir-ts`: identity is the name,
so both keys read and write the same storage. Loading this module makes every
default transform out of Three objects, which the 3D renderer, camera and
physics rely on.

### Scene

```ts
interface Scene {
    skybox?: SkyboxDescriptor;
    setSkybox(skybox: SkyboxDescriptor | undefined): void;
    removeSkybox(): void;
    hasSkybox(): boolean;
}
```

- `skybox`: This scene's skybox, read by the skybox system. Set it with `setSkybox`.
- `setSkybox`: Sets the skybox for this scene, or removes it with `undefined`.
- `removeSkybox`: Removes the skybox from this scene.
- `hasSkybox`: Whether this scene has a skybox that is not disabled.
